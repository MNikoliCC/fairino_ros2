# FAIRINO speed configuration

> **Safety-related changes.** Safety speed, reduced mode and collision level
> are safety functions of the FAIRINO controller. Change them only under the
> site's risk assessment, by authorized personnel, first on SimMachine and
> then on the real robot at a controlled starting speed. This stack never
> changes a safety parameter automatically or during recovery, and every
> change it can make is confirmed by the operator and audited.

## 1. Four different speed layers

They are independent. Raising one does not raise the others, and raising a
safety threshold does **not** raise the physical maximum of the robot.

| # | Layer | What it limits | Value in this stack | Changed via |
|---|---|---|---|---|
| 1 | **Software / OInK limit** | the joint command generated by our solver | J1–J3 120 deg/s, J4–J6 180 deg/s (× `velocity_scale`), 540 deg/s², Cartesian 1.0 m/s and π rad/s, filter τ 0.05 s | `fairino_cartesian_servo.yaml` / launch |
| 2 | **FAIRINO global speed scaling** | FAIRINO motion commands (MoveJ/MoveL/…) | SimMachine: manual 100 %, automatic 30 % | Viser *Apply Global Speed* → `SetSpeedInstant` |
| 3 | **FAIRINO safety speed** | controller supervision of joint/TCP speed | not readable through SDK 3.9.9 | WebApp *Initial Setup → Safety → Safety Speed*; `SetVelReducePara` (SimMachine only) |
| 4 | **Physical / model maximum** | the robot hardware | FR20: J1–J3 120 deg/s, J4–J6 180 deg/s, TCP 2 m/s typical | cannot be changed |

```text
SetSpeed(100)          = request for full global speed scaling (layer 2)
SetVelReducePara(...)  = safety-speed protection configuration (layer 3)
RoboPlan VelocityLimit = limit of the joint command our solver generates (layer 1)
```

The OInK limits are **not removed**: they are set to the documented FR20
maxima. Without velocity/acceleration limits OInK can produce numerically
valid but physically unacceptable steps that cause exactly the overspeed
faults recovery would have to handle. The goal is the maximum documented
speed, not an uncontrolled command.

## 2. API calls used

| Call | Where | Parameters | Notes |
|---|---|---|---|
| `SetSpeed(int vel)` | `/fairino_robot/set_global_speed` (`instant: false`) | 1..100 % | global speed |
| `SetSpeedInstant(int vel)` | `/fairino_robot/set_global_speed` (`instant: true`, used by Viser) | 1..100 % | takes effect immediately |
| `SetVelReducePara(int enable, double maxTCPVel, int strategy, std::vector<double> maxJointVel)` | `/fairino_robot/set_safety_speed` | enable 0 disabled / 1 manual mode / 2 all modes; maxTCPVel 0–1000 mm/s (SDK doc); strategy 0 stop+alarm / 1 automatic limiting / 2 stop+alarm+disable; 6 joint limits deg/s (documented default 45) | refused unless `allow_safety_config_writes:=true`; strategy 1 only with enable 1 |
| `SafetyOPPasswordCheck(0, password)` | `/fairino_robot/set_safety_speed` when a password is given | safety operation password (WebApp default `12345678`, changeable under System Settings → Maintenance Mode → Safety Parameter Configuration) | the password is never logged |
| `GetRobotRealTimeState()` fields `speedScaleManual`, `speedScaleAuto`, `collisionLevel[6]` | `/fairino_robot/status` | — | the CNDE value is a **fraction 0..1** (SetSpeed(50) reads back 0.5), shown ×100 |
| `ServoJ(..., acc, vel, cmdT, filterT, gain, ...)` | `write()` | `acc = vel = filterT = gain = 0`, `cmdT = 0.001` | the SDK header marks `acc`, `vel`, `filterT`, `gain` as "not open yet, default 0" |

No SDK getter exists for the safety-speed configuration (`SetVelReducePara`
is write-only in SDK 3.9.9). The old value of a safety-speed change can
therefore not be read back: the audit records "not readable via SDK 3.9.9" as
the old value and the WebApp must be used to verify.

Every request is audited (`/fairino_robot/events`, ROS log `AUDIT [speed]` /
`AUDIT [safety_config]`) with requester, reason, old value, new value and SDK
return code, including refused requests.

## 3. Global speed (layer 2) — measured

SimMachine 3.9.9, robot in manual mode, 2026-10-14:

| Action | Old | New (read back) | Code |
|---|---|---|---|
| initial state | — | manual 100 %, automatic 30 % | — |
| `SetSpeedInstant(50)` | manual 100 % | manual 50 % (CNDE 0.5) | 0 |
| `SetSpeed(30)` | manual 50 % | manual 30 % | 0 |
| `SetSpeedInstant(100)` (restore) | manual 30 % | manual 100 % | 0 |
| `SetSpeedInstant(20)` / `(5)` and restore to 100 % during the ServoJ tests | 100 % | 20 % / 5 % → 100 % | 0 |

Only the scale of the active mode changes (manual here).

**Effect on ServoJ.** The same servo trajectory (circle r = 0.10 m, 2 s) gave
the same joint speeds at 100 % and 20 % (J3 49.5 vs 50.1 deg/s), and a faster
circle at **5 %** (J1 ≈ 50 deg/s, far above 5 % of the joint limit) ran 80 s
without a fault. Global speed scaling therefore does **not** slow down ServoJ
and does not scale its speed limit. `SetSpeed(100)` cannot make ServoJ faster
either: the servo speed is set only by the command stream (layer 1). The two
`main=1 sub=23` faults observed at 20 % and 5 % coincided with simulator
stalls that produced a large single ServoJ step; after the per-point step limit
was added to the hardware plugin, a 60 s run at 5 % with two simulator stalls
produced no fault. FAIRINO's FAQ notes that each
classic motion command has its own velocity argument (default 20) that must be
100 to use the full global speed — this applies to MoveJ/MoveL, not to ServoJ
([FAIRINO FAQ](https://support.fairino.us/portal/en/kb/articles/fairino-faq)).

For reference, the controller's own planner on SimMachine (MoveJ, vel = acc =
ovl = 100 %, one joint moved) reached **180 deg/s and 541.7 deg/s²** on J1, J2
and J6 (J1 alone: 180 deg/s although the published FR20 J1 maximum is
120 deg/s; the SimMachine model is more permissive than the real robot). The
OInK acceleration limit of 540 deg/s² is taken from this measurement because
FAIRINO publishes no FR20 joint accelerations.

## 4. Safety speed (layer 3) — measured on SimMachine only

Procedure: stack launched with `allow_safety_config_writes:=true`, requests
through `/fairino_robot/set_safety_speed`, robot in manual mode.

| Request | Result |
|---|---|
| enable 1, 100 mm/s, strategy 0, joints 30 deg/s, **without confirmation** | refused by the plugin (audited) |
| enable 2 (all modes) with strategy 1 (automatic limiting) | refused: automatic limiting is only available with manual-mode enable |
| enable 1, 100 mm/s, strategy 0, 30 deg/s, confirmed, no password | `SetVelReducePara` code 0 |
| same with password `12345678` | `SafetyOPPasswordCheck` 0, `SetVelReducePara` 0 |

Effect:

| Motion | Safety speed | Observed |
|---|---|---|
| MoveJ J1 +60°, vel 100 % | disabled | J1 146.9 deg/s, TCP 2213 mm/s, completed |
| MoveJ J1 +60°, vel 100 % | manual, stop + alarm, 30 deg/s, 100 mm/s | stopped after 0.6° (J1 15.1 deg/s, TCP 227 mm/s); no main/sub code was set |
| MoveJ J1 +60°, vel 100 % | manual, automatic limiting, 30 deg/s | J1 capped at exactly 30.0 deg/s (TCP 452 mm/s), completed in 2.1 s |
| ServoJ servo circle | manual, stop + alarm, 30 deg/s, 100 mm/s | **no effect**: joints up to 50.9 deg/s, 0.31 m/s, no stop, no code |

**Consequence:** on SimMachine 3.9.9 the safety-speed function supervises
MoveJ but not the ServoJ stream. In servo mode, layer 1 (OInK/Cartesian limits)
and the controller's joint command speed fault (1/23–28) are the speed limits
that actually act. This must be verified on the real robot before relying on
safety speed during servoing.

After the test the configuration was restored with
`SetVelReducePara(0, 250, 0, [45…])` (disabled). The original value could not
be read; "disabled" matches the behaviour before the test (MoveJ reached
180 deg/s and 2.2 m/s in manual mode). The real robot's configuration must be
read in the WebApp and recorded before any change.

### WebApp procedure (when the API is not sufficient)

The SDK cannot read the safety-speed configuration, so the WebApp is the
reference ([FAIRINO 3.9.9 safety manual](https://fairino-doc-en.readthedocs.io/3.9.9/CobotsManual/safety.html)):

1. Open the FAIRINO WebApp (`http://<controller-ip>`; SimMachine: `http://192.168.58.2`, admin / 123).
2. Open **Initial Setup** (older versions: *Initial Settings*).
3. Open **Safety**.
4. Select **Safety Speed**.
5. Enter the safety operation password if asked (default `12345678`; change it
   under System Settings → Maintenance Mode → Safety Parameter Configuration).
6. Choose the function state: **Disable**, **Manual Mode Enable** or **All Modes Enable**.
7. Enter the TCP speed limit (the 3.9.9 manual gives 1–1500 mm/s for the
   manual TCP speed; the SDK documents 0–1000 mm/s) and the J1…J6 speed limits.
8. Choose the overspeed strategy: **Stop and Alarm**, **Auto Speed Limit**
   (only available with Manual Mode Enable) or **Disable After Stop and Alarm**.
9. Save/apply the configuration.
10. Re-read the page and record the values (old and new) in the cell log; the
    stack's audit log records only what was sent through the API.
11. Test first on SimMachine, then on the real robot at a controlled starting
    speed.

The protection acts on whichever configured limit is exceeded first (in the
stop-and-alarm test above the 100 mm/s TCP limit stopped the motion while J1
was still below its 30 deg/s limit).

### Reduced mode

Speed reduction levels are configured separately
([FAIRINO speed reduction mode](https://support.fairino.us/portal/en/kb/articles/speed-reduction-mode-configuration)):

1. **Initial → I/O Safety → DI/DO Safety Function**: assign the input that
   triggers the reduction mode (e.g. configurable input 1 or 2).
2. **Initial → Reduction Mode** (3.9.9: *Initial Setup → Safety → Reduced
   Mode*): select Level 1 or Level 2 and set the joint and TCP speeds.
   Level 3 stops the robot (SDK code 220 → LOCKOUT in this stack).

## 6. Collision sensitivity is not a speed limit

A false FAIRINO collision fault at higher speed must **not** be "fixed" by
lowering or disabling collision detection, and this stack never changes it
(collision faults are FAULT/operator; recovery never touches the collision
level). FAIRINO recommends keeping the collision level consistent with the
speed: about 10 % of the speed coefficient
([FAIRINO FAQ](https://support.fairino.us/portal/en/kb/articles/fairino-faq),
[collision level](https://www.fairino.us/cobots-knowledge-base/setting-collision-level)).
Levels 1–10 go from most to least sensitive; the current levels are shown
read-only in the Viser *Status* tab (SimMachine: 10 on every joint).

- WebApp: **Initial → Base → Joint → Collision Level** (3.9.9 manual: *Initial
  Setup → Safety → Joints → Collision Level*).
- SDK: `SetAnticollision(mode, levels[6], config)` — not used by this stack.
  Any change is a safety-related change and follows the warning at the top.

## 7. Raising speed safely

1. Keep all four layers in mind; start with a low `velocity_scale` (e.g. 0.25)
   on the real robot and raise it in steps.
2. Keep the FAIRINO global speed at 100 % for servoing (it does not change
   ServoJ) unless the risk assessment requires otherwise for other programs.
3. Read the safety-speed and reduced-mode configuration in the WebApp before
   the session; verify on the real robot whether safety speed supervises
   ServoJ (it did not on SimMachine).
4. Watch `servoj_flow_skips`, `servoj_point_limited` and the tracking error
   in the Viser *Status* tab; a FAULT for tracking error means the robot
   cannot follow the commanded speed.
